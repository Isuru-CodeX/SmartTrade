## 2024-03-24 - Batch Fetching Over `JOIN FETCH` for Collections
**Learning:** In `ContentService.java` (and similar services returning DTOs), using `LEFT JOIN FETCH` on `@OneToMany` relationships (like `Product` to `Stock`) can cause in-memory pagination warnings or Cartesian product performance degradation. Similarly, lazy loading them in loops causes N+1 queries.
**Action:** Replace `JOIN FETCH` on collections or lazy iteration in loops with explicit batch fetching: collect the main entities in the first query, then run a secondary query `FROM Stock s WHERE s.product IN (:products)` and group by the parent ID to map them together in Java. This significantly improves load times for product lists.
